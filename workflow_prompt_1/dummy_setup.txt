TIMESTAMPS, READ THIS BEFORE SEEDING

Jira stamps Created itself and it cannot be backdated through the interface or the API. The master run picks its two prospects on the oldest Created date, so create the five issues one at a time in the exact order given below and let Jira stamp them in that order. All five will land within a few minutes of each other, which is expected and correct, and the master run reads Created at full timestamp precision rather than the date shown on a card.

A genuine tie on Created cannot be seeded for the same reason, so the Priority tie break in the master brief stays untested by this data. Do not try to backdate anything, do not write a fake created date into a field, and do not hold off on seeding because the timestamps sit close together.
