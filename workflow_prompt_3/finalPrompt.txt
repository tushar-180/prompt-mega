Every scope item ends up in exactly 1 of 5 states, never 2. Delivered is the clean case: in the SOW or an approved change request, its Jira issue Done with a resolution set, and a merged pull request in abc-retail-web or abc-retail-api behind it inside the window, though items with no code in them, documentation and training and that sort of thing, skip the pull request part. The sources do not carry equal weight. Agreement gets settled on paper, so the SOW and the change request log win, the closure thread next, the meeting notes below that, Slack at the bottom. Whether something got built runs on a different ladder, where a merged pull request beats a Jira status and a Jira status beats somebody claiming it in Slack. When the 2 ladders pull against each other, or the client says in writing that something is missing while Jira insists it is Done, the item is Disputed. Not Delivered.
