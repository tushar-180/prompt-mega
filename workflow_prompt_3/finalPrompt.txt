Here is where the judgment starts. Every scope item ends up in exactly 1 of 5 states, never 2. Delivered is the clean case: it is in the SOW or in an approved change request, its Jira issue in ABCR reads Done with a resolution set, and a merged pull request in abc-retail-web or abc-retail-api sits behind it inside the window. Items with no code in them at all, documentation and training and that sort of thing, skip the pull request part. Delivered with Deviation is where it shipped but not the way the SOW or the change request log described it, and the gap between the 2 gets spelled out in a line of its own. Deferred is where somebody agreed to it in writing, in the SOW, the change request log, the closure thread, the Slack channel abc-retail-project or the closure meeting notes, and it never got a Done issue or a merged pull request. Dropped is where the client pulled it, in the closure thread or at the closure meeting, and whoever pulled it and where gets named. Disputed is where the sources argue with each other.

The sources do not carry equal weight. Agreement gets settled on paper, so the SOW and the change request log win, the closure thread comes next, the closure meeting notes below that, and Slack sits at the bottom. Whether something actually got built runs on a different ladder. A merged pull request beats a Jira status there, and a Jira status beats somebody claiming it in Slack. When the 2 ladders pull against each other, or the client says in writing that something is missing while Jira insists it is Done, the item is Disputed. Not Delivered. A green board settles nothing. Every Disputed item gets written up with both sides and the exact source sitting behind each, so somebody picking it up later can see what you saw.
